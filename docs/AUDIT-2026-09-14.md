Date: 2026-09-14. All inspection, changes, and verification in this continuation
were performed in the primary session, without subagents. Earlier conclusions
were not used as evidence. The initially modified Messages parser was reviewed
again and independently regression-tested.

## Acceptance Status

## Findings Addressed

### Security

- Removed unauthenticated raw-token HTTP responses and wildcard CORS. Added
  local API-key authentication for both standard credential header formats,
  loopback Host validation, browser-origin rejection, and key-required remote
  binding. Conflicting or duplicate credentials are rejected.
- Prevented upstream diagnostic bodies from being reflected to clients. Kept
  meaningful HTTP status/retry information and stable common capability-error
  markers without exposing raw provider details.
- Added request shape/size checks and rejected request-body attempts to override
  server transport settings. Disabled credential-bearing redirects and required
  HTTPS for non-loopback upstream base URLs.
- Removed Copilot token logging. GUI no longer passes GitHub credentials through
  process arguments. Credential-file updates use atomic replacement and Unix
  owner-only permissions where supported. Windows storage is still protected by
  the user's directory ACLs, not an OS credential vault.
- Hook failures no longer silently succeed. Added session-ID path validation,
  bounded hook input/output/runtime, explicit command-hook opt-in, and metadata-only,
  bounded observation logging. Updated current Claude hook field aliases.
- Skill downloads validate paths, reject symlink/junction ancestors, check HTTP
  errors and size limits, select a fixed upstream revision, and preserve existing
  local files. Downloaded skills remain third-party content, not trusted code.
- URL opening no longer builds a `cmd start` command from upstream text. Device
  links are restricted to GitHub's device authorization URL. Generated CLI
  configuration commands safely quote values and reference keys indirectly.

### Compatibility And Reliability

- Corrected standard Anthropic message deserialization and token-count requests
  without `max_tokens`; added consistent API error envelopes.
- Added native Copilot Messages routing based on upstream `supported_endpoints`.
  Native forwarding preserves thinking/signatures, modern tool and cache fields,
  protocol capability headers, and streamed pings without rewriting the payload.
- Removed silent Claude-to-GPT substitutions and fabricated model catalogue
  entries. Added upstream-backed model spelling resolution and desktop discovery
  metadata. Model availability remains dependent on the account and upstream.
- Preserved modern OpenAI/Responses request options, image inputs, function-call
  arguments, tool results, and usage conversion. Fixed streamed tool arguments
  being treated as text and premature closure of parallel tool blocks.
- Unified translated SSE framing across LF/CRLF/CR, optional spaces and arbitrary
  transport splits, with buffer limits and errors for incomplete streams.
  Features that legacy conversion cannot represent are explicitly rejected.
- Fixed Copilot token expiry handling and duplicate refresh loops with single-flight,
  on-demand refresh. Validated dynamic Copilot API endpoints. Added expiring GitHub
  OAuth credential storage/refresh and bounded device-flow handling for denial,
  expiration, pending authorization, and slow-down responses.
- Separated GitHub REST version `2026-03-10` from Copilot's protocol version.
  Replaced third-party editor-version scraping with Microsoft's official endpoint.
- Fixed rate-limited concurrent requests being released together; added queued
  slot reservation, bounded waits, HTTP 429, and `Retry-After`.
- Corrected Azure Responses to the stable `/openai/v1/responses` route, validated
  deployment identifiers, and encoded query/path parameters structurally.
- Fixed GUI device authorization being killed immediately after displaying a
  device code. Added owned-process cleanup and exit status handling.
- Replaced size-only executable cache checks with content-addressed, verified,
  atomically written server caches. Build output now uses `OUT_DIR`; release GUI
  builds fail if no server is available to embed.
- Fixed Unicode log/version truncation, unsafe proxy credential interpolation,
  unquoted Windows autostart paths, and invalid numeric fallback behavior.
- Removed automatic global Claude configuration changes on GUI start/save.
  Configuration is an explicit action that preserves unrelated settings and
  rejects malformed existing files. Desktop App uses its separate Gateway setup.
- Added locked builds, test/Clippy/format gates, dependency scanning, current
  Action versions, scoped release permissions, and weekly dependency updates.

### Continuation Findings

- Tested actual GitHub device authorization, denial, OAuth rotation, credential
  replacement, and 16-way concurrent refresh through isolated HTTP fixtures.
  Added absolute `COPILOT_DATA_DIR` support for isolated credentials.
- Preserved Anthropic model-discovery version headers and 429 responses. Empty
  upstream keys are rejected; native JSON responses have bounded reads and
  content-type/shape checks. Oversized client bodies retain HTTP 413.
- Verified the current official SDK rather than relying on old protocol rules:
  native Messages accepts its `system` message role and `max_tokens: 0` cache
  prewarming. The latter cannot be downgraded to a generation request.
- Accepted empty tool results; preserved strict tool schemas, embeddings output
  options, named Responses tool choices, and repeated streaming argument metadata.
  Unrepresentable message-level cache, citation, or tool-error semantics require
  native Messages instead of being silently discarded.
- Unified missing post-request hooks across native, translated, OpenAI, and Azure
  routes. Stream hooks report response acceptance, not successful stream completion.
  Observation startup failures are reported; bounded metadata logs can be flushed
  before CLI/server exit. Session files use full IDs and counters use file locks.
- Windows quoted command hooks work with executable paths containing spaces;
  bounded hook execution terminates owned descendant processes through Job Objects
  or Unix process groups. CLI errors now propagate nonzero status; skill downloads
  use immutable revision URLs and atomic no-clobber installation.
- GUI provider selection is explicit, including custom Anthropic gateway hosts.
  Provider keys and request intervals have usable controls; stale inherited
  credentials are cleared. Model discovery retains only actual valid upstream IDs.
- GUI configuration uses atomic writes and structured Azure URLs; clearing a
  model removes stale Claude overrides. Authentication cannot launch after the
  GUI closes. Dependency checks cap runtime and output, and clean up owned trees.
- Real GUI callbacks are tested with recorded desktop services, isolating browser,
  clipboard, and autostart actions. The concurrent branding/language changes were
  preserved and included in the final tests: software-rendered pages, controls,
  light/dark themes, language selection, and embedded icons.

### Coverage

LLVM instrumentation was applied to each root test target, including all isolated
fixture processes, with separate profile names for each source revision.
[report-coverage.ps1](../scripts/report-coverage.ps1) counts distinct source lines
from LLVM LCOV `DA` records. Rust symbols and `cfg(test)` declarations jointly
identify test-only ranges; production functions after test modules and production
generics instantiated with test types stay in the denominator. LLVM's overlapping
async-function summary counts are recorded separately, not treated as extra lines.

- Server: **3970 / 4803 production lines, 82.66%**.
- GUI: **1220 / 1435 production lines, 85.02%**.
- Both exceed the repository's 80% target. Neither is 100% coverage. In particular,
  interactive CLI, real desktop operations, and some error paths remain unexecuted.
- Generated Slint code, dependency macros, build scripts, other platform branches,
  and files with no LLVM mapping are outside this measurement and explicitly
  identified in the report. This is not whole-repository or branch coverage.
- Initial 55.45%/25.98% and intermediate reports included tests or older revisions;
  they are historical and not comparable production-only acceptance figures.

To reproduce, use matching LLVM tools (`llvm-cov`, `llvm-profdata`, `llvm-cxxfilt`)
and compile each test target with `cargo rustc --tests -- -C instrument-coverage`.
Use a fresh `LLVM_PROFILE_FILE` containing `%p-%m`, run the emitted test executable,
merge only those profiles, then invoke the reporter with `-Executable`,
`-ProfileData`, `-SourceRoot`, `-OutputPath`, and `-MinimumPercent 80`.
Run `./scripts/report-coverage.ps1 -SelfTest` to verify the counting rules. Do not
reuse profiles after source edits or formatting; verify the source hashes too.
